# 006 · 交付物是给人脑加工的坯料;skill 协作要写"说明 md"

2026-07-28

## 一、交付物分两态:可锻的(自用)vs 冻结的(对外)

投研分析的最终稿,**一定要过人脑**。AI 在对话里给我**启发 + 好的表达**;但我有**审美**,我会改逻辑关系、用 AI 的好表达去 polish 我自己的表达。**AI 供料 + 打磨,我署名。**

所以交付物按用途选形态:

| | 形态 | 为什么 |
|---|---|---|
| **自用** | **md**(可锻态) | 便于我随时改;读它的时候会冒出对 skill 的修改想法——md 摩擦最小 |
| **对外** | **Word / PPT**(冻结态) | 成品,给别人看的,要排版和正式感 |

> 别用网页当自用交付物——它是"冻结的成品",挡住了我继续捶打它的手。md 是**半成品坯料**,才留得住"我还要改"的空间。

## 二、读交付物 → 改 skill → 归集"修改逻辑" = 复利引擎

关键不在交付物本身,在这个回路:
- 交付物 = **用这个 skill 跑的一次实验**;
- 读它时冒出的改进 = **skill 的进化**;
- 而"**我为什么这么改**"(归集下来的修改逻辑)= 我的**判断力和审美**的沉淀——**这比 skill 本身更值钱**。

**建议:给每个 skill 配一个"修改逻辑 log"**(像 changelog,但记的不是"改了啥",是"**为什么这么改**")。这是你审美的年轮。

## 三、skill 协作不是傻瓜拼接,中间要写"说明 md"

对外要 Word/PPT 时,分析 skill 要和 `pptx` / `docx` 这类 skill 合作。但**两个 skill 不能傻傻对接**,中间需要一份**说明 md(接口契约)**,讲清:
- 分析 skill **输出什么结构**(章节 / 字段 / 结论卡);
- 排版 skill **怎么消费**它(哪段进哪张 slide、模板长啥样);
- 交接时的取舍(哪些自用细节对外要砍)。

> 这类"说明 md"就是 skill 之间的**胶水文档**(像 skill-vs-resource、视角对照那种)。**一堆 skill 要成为能协作的网,靠的就是这些胶水,不是把它们堆在一个目录里。**

## 一句话

**自用交付物用 md（留着继续锻它），对外用 Word/PPT（冻结交付）；读交付物时的改动喂回 skill，改动背后的"为什么"才是你的审美资产；skill 要协作,先写清它们之间的接口说明。**
