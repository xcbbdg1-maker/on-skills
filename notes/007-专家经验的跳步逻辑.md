# 007 · 专家经验的“跳步逻辑”:不能只提取结论,要反编译成可执行判断

2026-07-29

这是我和 Codex 在迭代 `pevc-financials-lens` 时暴露出来的一个真实问题,也是对 [002 · 用别人的文章做成一个 skill](002-article-to-skill.md) 的进一步补充。

## 这段对话是怎么发生的

原文里有很多一线实务才会出现的判断,例如:

> 对 SaaS、AI 应用、企业服务、半导体设备、机器人零部件这类公司,收入质量往往比收入规模更重要。5000 万可续费、可扩容、边际交付成本下降的收入,可能比 1 亿元项目制、深度定制、依赖创始人逐单拿下的收入更好。

Skill 最初并非完全没写收入质量:它提到了续费、扩容、标准化、项目制、销售驱动和经营杠杆。但它没有把“**5000 万高质量收入可能优于 1 亿元低质量收入**”变成必须执行的比较规则。

也就是说,观点被“提到”了,但真正使用时不一定会触发。后来才补上“规模—质量反转测试”、行业证据和交付自查。

第二个例子更典型。原文说:

> 毛利率是产业链位置、议价权、交付复杂度、规模化潜力、竞争格局的综合结果。

Skill 最初保留了这句话,看起来没有遗漏。但当我追问:“你只能看到毛利率,真的看得到其他东西吗?”问题立刻暴露:

- 毛利率只是结果,不能直接证明议价权;
- 只有三张表时,很多原因根本看不到;
- 完整年报/招股书只能提供间接证据;
- 产业链权力、购买原因和替代性最终仍要靠客户、供应商和竞品尽调;
- 如果 Skill 没写抓取路径、替代解释和停止条件,模型就容易把假设写成事实。

后来才把它补成“毛利率驱动树”:毛利桥 → 单位层 → 跨表验证 → 跨期/同行验证 → 证据分级 → 待尽调问题。

## 真正的问题:专家写的是压缩后的认知

一线专家经常只写最后一句,因为中间几步对他来说已经是常识。他看到一个数字时,脑中会自动调用合同、客户、成本、组织、行业和历史案例,但文章里未必把这些步骤展开。

例如“毛利率反映议价权”,背后的完整链条可能是:

```text
毛利率变化
→ 拆产品结构、价格和成本
→ 看折扣、返点、账期、客户集中度和成本传导
→ 排除产品 mix 等替代解释
→ 判断客户还是公司掌握交易权力
→ 判断这种权力能否持续
→ 再决定它是否影响估值和投资判断
```

AI 很容易把专家的结论当成一条“知识”收进去,却没有意识到这是一段被压缩的程序。于是出现三种假覆盖:

1. **词语覆盖**:原文的名词在 Skill 里出现了;
2. **观点覆盖**:Skill 能复述作者的结论;
3. **执行缺失**:面对真实材料时,不知道何时触发、去哪里找证据、怎样排除其他解释、什么情况下必须停止判断。

所以,“提到了”不等于“会用了”。

## Skill 的最小单位不应是一句话,而应是一张判断逻辑卡

以后遇到专家式判断,不能只摘录或改写结论,要把它反编译为:

```text
【专家原话】他说了什么
【触发信号】看到什么现象时启动这条判断
【隐含变量】真正想判断的商业问题是什么
【中间链条】从信号到结论省略了哪些步骤
【数据抓取】需要从哪些报表、附注、合同或访谈取证
【交叉验证】用哪些其他数字或事实互相印证
【替代解释】还有什么原因会产生同样现象
【失效边界】在什么行业、阶段或会计口径下不能套用
【证据等级】这是事实、财务推断、外部佐证还是待尽调假设
【停止条件】数据不足时结论必须停在哪里
【投资动作】最终影响尽调、估值、条款还是投/不投
【输出句式】实际报告中必须怎样表达,避免把假设写成事实
```

只有这些元素进入 Skill,专家经验才从“观点”变成“可执行程序”。

## 对文章转 Skill 流程的修正

原来的流程是:

> 通读补全 → 对照审计 → 真材料实跑 → 啃透名词

现在要在“通读补全”和“对照审计”之间增加一步:

> **识别跳步判断 → 反编译隐含逻辑 → 再写进 Skill**

完整流程应变成:

1. **原意提取**:作者明确说了哪些事实、指标和结论;
2. **跳步扫描**:找出所有从数字直接跳到商业判断的句子,尤其是“意味着、反映、说明、多半、本质上、决定、投影”等表达;
3. **逻辑反编译**:还原触发信号、中间假设、数据来源、反证、边界和投资后果;
4. **可执行编码**:写成步骤、证据表、判断规则、停止条件和输出格式;
5. **反例测试**:用同一现象但原因不同的案例,检查 Skill 会不会机械套用;
6. **真实材料实跑**:验证模型是否真的会抓数据、做归因并控制结论强度;
7. **回填 Skill**:把失效点写回规则和自查,而不是只修一次输出。

## 新的“覆盖”标准

以后审计 Skill 是否覆盖原文,不能再问“这句话有没有被写进去”,而要问:

- 真实材料出现这个信号时,模型会不会主动触发这条判断?
- 它知不知道去哪里取证?
- 它能否还原中间因果链?
- 它会不会检查替代解释和反证?
- 它知道什么时候信息不够、必须停止吗?
- 它会把判断落实到尽调、估值、条款或投资决策吗?

六问都能回答,才叫真正覆盖。

## 这次得到的一句话

> **专家框架最有价值的,不只是他写出来的判断,而是他认为“不必写”的那些中间步骤。把别人的框架做成 Skill,真正要提取的是这套被压缩的一线认知程序。**
