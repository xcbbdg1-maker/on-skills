# 005 · 怎么判断一个(投研)skill 好不好:读它的 md,看框架"活不活"

2026-07-28

市面上投研分析类 skill 一大把,重复造轮子的居多。怎么筛?**别看它 star 多少、包装多炫,去读它的 SKILL.md,看背后的分析框架是"活的"还是"死的"。**

## 核心判据:框架是不是"活的"

好 skill 沉淀的是**一套活的分析框架**,不是一张指标清单。活的框架有三个特征:

1. **有前后逻辑关系(递进,不是并列)**:告诉你**先看什么、再看什么、为什么这个顺序**。(如"收入真不真 → 赚不赚 → 活不活 → 扩得值不值 → 退不退得出"——前面不成立后面白搭。)
2. **有抓大放小的侧重点**:告诉你**这次该重点看哪几个、哪些可以放**。一线经验最值钱的不是"知道所有指标",而是"**知道这一单该盯哪里**"——这是**注意力的分配**。
3. **有具体阈值 / 真实案例 / 踩过的坑 / 诚实的边界**:如"LTV/CAC>3 才健康""VHSI>25%+南向连续流出=窗口关""这做不了商业尽调"。

## "死"的迹象(多半是给 AI 几个提示词生成的)

- 平铺直叙的 exhaustive 清单,什么都提一句,**没有优先级**;
- 满是"需关注 / 有待观察"这类正确的废话;
- 没有取舍、没有 war story、没有"哪个更重要"的判断。

> **关键:AI 能生成"所有指标的清单",生成不了"抓大放小的注意力"。** 后者只能从真实业务经验里长出来。所以框架活不活,基本等于"作者有没有一线经验"。

## 用轮子的正确姿势

1. **先读 md**,用上面判据筛:框架活的 / 作者有一线经验的,才值得拿。
2. 选中后,**把它当种子迭代成自己的**(见 [001](001-skill-acquisition-loop.md))——用一线经验做的框架当底座,比从零造、或拿"AI 提示词生成的空壳"改,**效率高得多**。
3. 观察造轮子的人:**是一线从业者沉淀的,还是给 AI 提示词攒的?** 前者的 skill 才有"活框架"的内核可嫁接。

## 一句话

**判断一个 skill,不看它长得多全,看它敢不敢告诉你"先看这个、这个最重要、这个我也做不了"——敢,就是活的、有人味的;不敢、只会面面俱到,多半是空壳。**
