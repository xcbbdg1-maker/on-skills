# 020 · 比较 Skill，要分开方法内核与产品外壳

2026-07-31

## 这段对话

> GitHub 上有类似的看财报项目吗？你觉得我做的和他们比起来谁更好？

这个问题不能只用一个总排名回答。调研同类项目后，比较清楚的结论是：

- 如果比完整、公开、可安装的金融 AI 产品，`FinRobot` 明显更成熟；
- 如果比工程可靠性、工作流恢复和证据检索，`FinSight-AI`、`SEC Insights` 各有明显优势；
- 如果比 A 股、港股、美股的自动取数、行情、新闻和推送，`ClarityFinance` 更宽；
- 如果只比“用 PEVC 视角深读一份招股书，形成有证据边界、可反驳、能进入下一步尽调的投资判断”，`pevc-financials-lens` 反而有自己的强项。

真正的问题不是笼统地问“谁更好”，而是先问：**比较的是方法内核，还是产品外壳？**

## 同类项目实际在做不同的事

这次选取了几类代表项目：

| 项目 | 主要解决的问题 | 强项 |
|---|---|---|
| [FinRobot](https://github.com/AI4Finance-Foundation/FinRobot) | 自动化股票研究和估值 | 多 Agent、确定性估值、数据接口、桌面产品、IC 报告 |
| [FinSight-AI](https://github.com/juanjuandog/FinSight-AI) | 可恢复、可追溯的股票研究工作流 | 任务恢复、快照绑定、混合检索、证据追踪、RAG 评测 |
| [SEC Insights](https://github.com/run-llama/sec-insights) | 对 SEC 文件做带引用的问答 | 文档检索、引用、高亮、交互式 PDF 阅读 |
| [ClarityFinance](https://github.com/cooragent/ClarityFinance) | 多市场股票分析和持续跟踪 | 多数据源、技术面、基本面、新闻、情绪、筛选和推送 |
| [Financial Analysis Agent Skill](https://github.com/QYQSDTC/Financial_Analysis_Agent_Skill) | 自动计算财务指标并评分 | 30 多个指标、杜邦分析、趋势分析、Markdown/Excel 输出 |
| [ai-hedge-fund](https://github.com/virattt/ai-hedge-fund) | 多投资人格的交易决策实验 | 多 Agent、回测、Web 产品和社区传播 |

这些项目都可以被叫作“看财报”或“金融 Agent”，但实际任务并不一样：有的是文件问答，有的是指标计算，有的是股票筛选，有的是交易实验，有的是完整研究平台。把它们放进一个榜单，只按 star、文件数量或功能数量排序，会掩盖真正的能力差异。

## 一个金融 Skill 至少有六层能力

以后比较同类项目，可以拆成六层：

### 1. 方法与判断内核

它是否告诉 AI：

- 先看什么、后看什么；
- 哪些信号最重要；
- 事实怎样经过商业机制变成判断；
- 有哪些竞争性解释；
- 结论最多能说到哪里；
- 什么证据会推翻当前判断。

这是 `pevc-financials-lens` 目前最强的一层。它不是把 ROE、毛利率、应收周转率列成清单，而是把财务数字重新翻译为收入质量、终端需求、经营杠杆、现金自我融资、资本依赖和退出可行性。

### 2. 确定性计算层

公式、口径桥、DCF、LBO、WACC、可比公司、敏感性分析和 Monte Carlo 是否由代码计算并留下输入、公式和结果，而不是交给语言模型心算。

这一层 `FinRobot` 和传统财务分析库更强。`pevc-financials-lens` 虽有基础比率复核，但还没有形成完整、模块化、可测试的估值与财务计算引擎。

### 3. 证据与可追溯层

结论能否回到原始页码、截图、表格、版本和数据快照；能否区分原文、计算值、公开信息推断和必须进一步尽调的事项。

`pevc-financials-lens` 对证据边界、原始证据贴片和可推翻条件要求很高；`FinSight-AI`、`SEC Insights` 则在检索、快照、引用和系统化追踪上更成熟。前者更像专业判断协议，后者更像工程化证据基础设施。

### 4. 执行与自动化层

能否自动取得文件、识别表格、选择数据源、缓存中间结果、断点恢复、重试失败步骤，并稳定批量处理多家公司。

这一层是当前 `pevc-financials-lens` 的明显短板。一次报告可以做得很深，不等于系统已经证明自己能稳定地连续运行。

### 5. 输出与产品层

有没有 Web UI、API、桌面端、交互式图表、报告版本、任务状态和一键部署；最终用户是否不需要理解 Skill 文件也能使用。

`FinRobot`、`FinSight-AI`、`SEC Insights` 已经在做产品，`pevc-financials-lens` 当前仍主要是一个供 Agent 执行的专业方法系统。深度报告是高质量交付物，但还不是完整产品。

### 6. 真实回归与可信度层

有多少真实案例；是否跨行业、跨周期；失败案例有没有回写；判断能否在事后被验证；有没有基准集和回归测试。

这是所有“看起来很完整”的 Skill 最容易忽略的一层。一个项目有几十个 Agent、几百个文件或很多 star，不自动证明它的投资判断可靠；反过来，一个私有 Skill 有一份很深的报告，也不能证明它已经跨行业成立。

## `pevc-financials-lens` 真正领先的地方

它的优势不是功能多，而是对一些容易被误判的投资问题切得很细：

- 区分公司向经销商销售、渠道库存、终端销售、安装使用和终端复购；
- 不把产能利用率自动当成销量，不把订单自动当成收入；
- 不把经销商留存或经销商净收入留存率直接解释为终端客户留存；
- 不从费用率下降直接跳到“产品自然拉动增长”；
- 区分公开披露可验证、公开信息推断和必须一级尽调；
- 要求每个重大结论写明直接证明什么、不能证明什么、什么会推翻；
- 把利润表继续传导到现金、Runway、资本结构、交易价格与退出准备度。

这是一套偏一级市场的**投资判断内核**，而不是普通财务比率计算器。它在港股招股书、经销模式、客户集中、社保公积金不足、调整后利润和公开信息桌面尽调等场景中，已经形成比较明确的差异化。

## 不能因为内核好，就假装产品已经成熟

同样需要承认差距：

- 真实完整案例还少，跨行业稳定性没有充分证明；
- 确定性计算和自动化测试不足；
- 没有成熟的 PDF 摄取、结构化表格提取和多数据源切换；
- 没有完整的 DCF、LBO、可比公司和情景估值引擎；
- 没有任务恢复、数据库、报告版本和基准评测；
- 没有让普通用户直接使用的 UI 或 API。

因此，更准确的评价是：

> `pevc-financials-lens` 已经有一台打磨得不错的专业判断发动机；FinRobot 等项目已经把数据、计算、Agent、报告和界面组装成整车。发动机有差异化，不等于整车已经造完；整车功能多，也不等于发动机里的判断一定更深。

## Star 不能回答“谁更好”

公开项目的 star 混合了很多因素：发布时间、传播能力、界面效果、题目是否吸引人、社区规模和是否容易运行。它可以说明项目受到多少关注，但不能直接回答：

- 财务定义是否准确；
- 投资判断有没有跳步；
- 证据边界是否诚实；
- 替代解释是否充分；
- 真实尽调中能否发现决定性问题。

这与 [005 · 怎么判断一个投研 Skill 好不好](005-怎么判断一个投研skill好不好.md) 的结论一致：**不要只看包装和指标清单，要看框架是否会分配注意力、是否敢做取舍、是否知道自己不能证明什么。**

但也不能反过来用“我更懂专业”掩盖工程短板。公开项目的产品化、自动化、测试和用户体验，都是能力的一部分，不只是外包装。

## 下一步不该照抄大而全，而要补齐自己的闭环

`pevc-financials-lens` 最合适的方向，不是复制一个拥有行情、新闻、技术指标和交易信号的大而全股票 Agent，而是把定位钉在：

> **PEVC Financial Due Diligence Engine：从财报、招股书和数据室材料中，生成可追溯、可反驳、能够进入投资委员会的尽调判断。**

围绕这个定位，优先补三层：

1. **真实回归层**：用制造、SaaS、消费、硬科技等至少 10 个案例检验同一框架，记录哪些判断成立、哪些失败；
2. **确定性计算层**：把口径桥、现金流重构、估值和情景分析做成代码模块，并为关键公式建立测试；
3. **证据化工作流**：把“PDF＋官方链接 → 证据包 → 判断卡 → IC Memo → 尽调问题清单”串成稳定流程。

如果未来公开，还应把公开方法、私有原始资料和私有案例拆开。方法可以公开，受限制来源和个人判断资产继续留在私有仓库。

## 这次得到的一句话

> **比较一个 Skill 和 GitHub 同类项目时，要把方法内核、确定性计算、证据系统、执行自动化、产品外壳和真实回归分开比较。小而深的 Skill 不会因为没有 UI 就失去专业价值，也不会因为报告很深就自动成为成熟产品。先判断自己要造的是一套判断方法、一台专业发动机，还是一辆可以交给别人开的整车。**
