# 017 · 先 quick 再 deep：把运行成本和输入策略写进 Skill

2026-07-30

这次用 `pevc-financials-lens` 跑来福谐波招股书时，我发现一个很实际的问题：Skill 越做越完整以后，一份完整招股书会同时触发大量取数、跨表重算、文字证据扫描、13 层测试、反证和结论回填。分析质量提高了，但普通的“先看看这家公司”也容易被自动跑成一次完整 deep，耗时明显增加。

这不一定是使用者哪里做错了，更可能是 Skill 没有把**判断目标、运行深度和停止条件**设计清楚。

> 第一次接触一家公司，不一定要立刻完成全套尽调式分析。先用 quick 判断值不值得继续研究；只有初筛通过或出现决定性问题，再进入 standard 或 deep。

## 这次真实运行暴露的问题

原来的 Skill 主要区分：框架解释、公开资料桌面测试、一级市场尽调、交易定价。这些分类回答的是“我现在拥有什么证据、最多可以下多强的结论”，却没有回答“这一轮到底要做多深”。

结果就是：

- 用户只是想先形成方向，Skill 却尝试覆盖全部 13 层；
- 完整招股书会触发多个专项 reference，读取和重算范围持续扩大；
- 发现一个异常后，分析可能自动进入更深测试，却没有明确告知使用者；
- 时间主要花在证明“完整”，而不一定花在回答当前最重要的问题。

因此，**证据边界**和**执行深度**必须拆成两条轴。

## 第一条轴：任务与证据边界

它回答“我们正在什么资料条件下工作”：

- **框架解释**：没有公司材料，只解释方法和所需数据；
- **公开桌面测试**：使用招股书、年报、公告和公开资料，只能形成公开信息初筛；
- **一级尽调**：取得数据室、合同、管理账、银行流水和访谈后，才可以形成更强的尽调判断；
- **交易定价**：除公司质量外，还要进入估值、资本结构、条款、稀释和回报。

执行得再深，也不能升级证据本身。`deep + 招股书` 仍然只是公开资料桌面测试，不等于一级市场完整尽调。

## 第二条轴：quick / standard / deep

它回答“这一轮做多深、什么时候停”。

### quick：先判断值不值得继续研究

适用于：

- “先看看这家公司”；
- “帮我判断值不值得继续研究”；
- 第一次收到项目或第一次打开招股书；
- 时间有限，需要先找到最可能改变决策的事项。

最低动作：

1. 建立主体、期间、币种、单位和资料边界；
2. 做收入、毛利、现金、应收、存货、资本开支等核心底表；
3. 对完整框架做轻量扫描，识别最咬公司的 3 个问题；
4. 只对决定“继续/停止”的异常做必要深挖；
5. 输出继续研究、暂缓或放弃的方向性判断；
6. 未执行的专项测试明确写“本轮未测试”，不能写“未发现问题”。

quick 的停止点是：已经足以回答“是否值得进入下一轮研究”。它不追求形式上的全套完成。

### standard：普通分析的默认档

适用于一般的“分析一下”“跑一下”。

它应完成框架全覆盖，但只深挖实际触发的 3—5 个关键层，并回答公司的生意质量、现金安全、结构性风险、可信度和退出基础。它比 quick 完整，但不自动进入交易定价和所有极端情景。

### deep：确认值得研究后再进入

适用于：

- 用户明确要求完整、逐层、IC、尽调或投资备忘录；
- quick/standard 已识别值得进一步研究的项目；
- 用户要求估值、交易价格、条款、MOIC/IRR；
- 重大异常需要完整证据桥、反证和压力测试。

此时才完整执行所有适用的专项测试、情景、证据附录和计算附录。

## 默认路由和升级规则

```text
先看看 / 值不值得继续研究
→ quick

普通“分析一下 / 跑一下”
→ standard

完整 / 逐层 / IC / 尽调 / 估值 / 条款
→ deep

完成一档后用户只说“继续 / 深入”
→ quick → standard → deep 逐级升级
```

重大异常可以触发“建议升级”，但不能在没有说明的情况下把 quick 静默扩成 deep。升级时要告诉使用者：发现了什么、为什么需要更多工作、升级后会多做哪些测试。

## 为什么最佳输入不是 PDF 和网页二选一

这次还明确了另一个实践规则：分析招股书时，最佳输入是：

> **本地可搜索 PDF + 官方网页链接**

两者承担不同角色。

### 本地可搜索 PDF：主分析底稿

适合：

- 全文搜索；
- 读取表格、脚注和会计政策；
- 固定页码引用；
- 建章节地图和按页文本；
- 重复运行时复用已经提取的底表；
- 避免网页加载、跳转或版本变化干扰。

如果是扫描版，应先做 OCR。相同版本不应每次重新解析，而应复用章节地图、文本缓存、关键页和计算底表。

### 官方网页链接：版本和时点锚

适合：

- 确认文件来自交易所、监管机构或公司官网；
- 核对发布日期、版本、修订和补充文件；
- 检查聆讯后资料、配发结果、上市结果和期后公告；
- 当本地 PDF 与最新披露冲突时，定位版本差异。

官方链接主要解决“这是不是最新、正式、完整的版本”，本地 PDF 主要解决“怎样高效、稳定、可复核地分析”。

只有其中一项也可以继续，但必须写明边界：

- 只有 PDF：可以分析，但可能漏掉修订和期后公告；
- 只有官方链接：先下载或缓存本地副本，再建立可复用底稿；
- 两者冲突：先调节版本，再进行计算和判断。

## 为什么这也是 Skill 设计的一部分

一个可靠的 Skill 不仅要告诉 AI“看什么、怎么算、怎么判断”，还要告诉它：

- 这一轮的目标是什么；
- 哪些动作现在必须做，哪些可以延后；
- 什么时候已经足够回答问题；
- 什么条件触发升级；
- 输入怎样组织，才能减少重复劳动；
- 结论强度是否超过当前资料边界。

如果没有这些规则，Skill 越完整，运行越容易失控。所有 reference 都是“可以调用的能力”，不是每次都必须从头到尾加载的清单。

## 一套可复用的开场卡

以后运行复杂分析型 Skill，开场先声明：

```text
【任务模式】框架解释 / 公开桌面 / 一级尽调 / 交易定价
【执行深度】quick / standard / deep
【本轮目标】要回答的一个核心问题
【输入状态】本地可搜索 PDF / 官方链接 / OCR / 版本日期
【本轮必做】核心底表和触发测试
【本轮不做】延后到下一深度的专项测试
【升级条件】什么发现会建议继续深入
【停止条件】达到什么结果就结束本轮
```

## 这次得到的一句话

> **复杂 Skill 不能只有“能力清单”，还要有成本意识和渐进式运行协议：用 quick 先筛选，用 standard 形成完整方向，用 deep 处理真正值得投入的问题；用本地可搜索 PDF 做可复核底稿，用官方网页链接守住版本和时点。深度应由决策需要驱动，而不是由材料有多长或 Skill 有多少条规则驱动。**
