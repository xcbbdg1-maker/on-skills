# 013 · 公开框架不等于可执行 Skill

2026-07-29

这次把一篇 PEVC 财务分析文章持续改造成 Skill 时，我意识到：

> 网上很多抽象描述和经验分享，其实不用太担心被别人轻易学会。看见、读懂和真正会用之间，还有一层很难的“抽象解码”。

一篇文章可以公开告诉所有人：

- 收入质量比收入规模重要；
- 毛利率要结合商业模式判断；
- 应收账款可能比利润重要；
- 存货背后藏着需求、供应链和产品迭代风险；
- 财报数字不能单点看。

但这些句子只是专家经验压缩后的输出。把它们复制进 `SKILL.md`，并不等于获得了专家的判断能力。

## 抽象描述省略了什么

专家写作时，常常已经在脑中走完一整条判断链，最后只留下一个简洁结论。

例如：

```text
消费公司收入增速放缓、存货持续上升，
可能说明渠道动销变差，后续清货会伤害毛利。
```

这句话背后其实省略了：

```text
适用于什么行业和阶段
→ 哪些信号必须同时出现
→ 还有哪些竞争性解释
→ 应该去哪里取数
→ 什么证据支持或推翻
→ 风险怎样传导至毛利和现金
→ 最终需要追问什么
```

如果 Skill 只保存“存货上升可能意味着滞销”，AI 很容易把经验写成公式：看见存货上升，就直接得出产品卖不出去。

真正的经验并不是这个结论，而是知道：

- 它可能是渠道动销变差；
- 也可能是正常季节性备货；
- 也可能是渠道扩张形成的增长占用；
- 还可能是新品上市前的合理准备。

然后知道该检查终端动销、渠道库存、退货、库龄、折扣、应收账期和期后销售，才能决定哪个解释更可信。

## 例子不是修辞，而是隐性经验的出口

过去我容易把文章中的“比如、例如、某类公司”看成帮助读者理解的修辞。在压缩成 Skill 时，往往只保留抽象原则，把例子删掉。

但后来发现，很多真正有价值的行业经验恰好藏在例子里。

抽象原则只说：

> 要关注存货质量。

行业例子却告诉你：

- 消费公司要看终端动销、渠道库存、退货、折扣和 SKU 库龄；
- 硬件公司要把原材料映射到客户订单、BOM、产品代际和物料通用性；
- 医疗器械还要看注册、效期、试用机和经销商铺货；
- 半导体和机器人要看长交期物料、客户验证、良率、发出商品和技术迭代。

这些差异不是从“存货”两个字自动推导出来的，而是作者在实务中积累的条件化知识。

所以，原文中的例子不应被原样堆砌，也不能被简单删除。它们需要被反编译成经验模式卡。

## 从文章到 Skill，需要四层解码

### 第一层：语义解码

先弄清作者说的词到底指什么。

例如“收入质量”不是一句价值判断，而可能包含：

- 续费和复购；
- 扩容；
- 标准化复制；
- 获客是否依赖关键人；
- 交付边际成本是否下降；
- 收入能否兑现为现金。

### 第二层：因果解码

不能停在“现象 → 结论”，要恢复中间机制和替代解释。

```text
观察信号
→ 原因假设A/B/C
→ 每种假设的支持证据
→ 反证与停止条件
→ 哪种解释目前更可信
```

### 第三层：执行解码

把判断变成 AI 真正会执行的程序：

```text
触发条件
→ 必须取数
→ 计算公式
→ 文字证据
→ 跨表/跨期/同行验证
→ 固定输出
→ 尽调问题
```

没有这一层，Skill 只是文章摘要。

### 第四层：校准解码

实务经验通常表达为“可能、往往、如果”，而不是真理。

Skill 必须保留：

- 证据等级；
- 替代解释；
- 不能下结论的条件；
- 公开信息和一手尽调的边界；
- 什么新证据会推翻当前判断。

否则，经验一进入 Skill 就会从启发式退化成机械公式。

## 公开知识为什么仍然不容易复制

别人可以复制一篇文章，也可以让 AI 帮忙生成一个看起来完整的 `SKILL.md`。但真正难复制的是：

- 能否识别作者省略了哪些中间步骤；
- 能否判断哪些例子承载行业经验；
- 能否生成合理的竞争性解释；
- 能否知道该取什么数据、看什么文字；
- 能否设置反证和停止条件；
- 能否在真实案例中发现 Skill 没有按预期工作；
- 能否把每次失败沉淀回测试、日志和案例库；
- 能否让多个 Skill 之间正确传递证据而不升级假设。

所以，真正的资产不只是原始内容，也不只是最终的 `SKILL.md`，而是：

```text
原文
+ 抽象解码方法
+ 行业经验模式
+ 反馈账本
+ 修改决策
+ 真实案例回归
+ Skill之间的协作系统
```

## 这也不意味着可以轻视公开分享

AI 会显著降低抽象解码的成本。今天很难复制的框架，未来可能更容易被还原。

因此，长期优势不能只依赖“别人看不懂”，而应来自：

- 更快的反馈循环；
- 更好的问题意识；
- 更丰富的反例和失败记录；
- 更真实的数据与案例；
- 更严格的验证协议；
- 持续演化的个人 Skill 系统。

公开分享的价值也正在这里：它提供了共同起点，但不会自动交付终点。

## 一条固定的原文解码协议

以后把文章、访谈或专家框架改造成 Skill 时，对每个抽象判断和行业例子执行：

```text
保留原文
→ 识别适用行业/阶段
→ 找到触发信号组合
→ 生成竞争性原因
→ 指定数字与文字证据
→ 设置反证和停止条件
→ 推导财务与投资后果
→ 映射到现有L/X层级
→ 用真实案例验证
```

如果只留下了一句更短、更工整的总结，而没有恢复判断程序，就不算完成了解码。

## 这次得到的一句话

> **公开框架只是专家经验的压缩包。别人可以轻易复制文字，却不能自动获得其中被省略的判断链；真正能形成壁垒的，是持续把抽象描述解码成可取证、可证伪、可执行、可迭代的 Skill 系统。**
