# 001 · 借用别人的 skill:跑起来 → 研读 md → 打磨适配

2026-07-27

## 核心

别人做好的 skill,对我的启发,**不是"用一下,然后评判它好不好用"**。

而是:能沉淀成 skill、还在 GitHub 上有 star 的,背后往往有一定真实案例的支撑。所以真正的用法是一个**获取循环**:

1. **先用它跑起来** —— 拿它真做一些行业分析,别光看;
2. **仔细研读它的 md** —— 看它内部是怎么搭的、把问题拆成了哪几层;
3. **修改打磨** —— 让这个 skill **和我的大脑适配**。

终点是:当这个 skill 的结构 = 我做判断时的结构,用起来零摩擦,它就"长到我脑子上"了。我不是它的用户,是它的改造者。

## 两点想清楚的

**① star ≠ 一定有真案例支撑。**
star 也可能是营销刷出来的。真伪不在 star 数,在"研读 md"那一步——看它有没有**具体阈值、真实案例、踩过的坑**,还是一堆"需关注 / 建议评估"的通用套话。
用我判断输出质量的同一把尺(要证据、防偷懒)去筛 skill 本身:一个写"VHSI>25% + 南向连续净流出=窗口关"的 skill,和一个全是正确废话的 skill,含金量天差地别。

**② 这个循环是双向的,不只是"我改 skill"。**
- skill → 我:跑和研读时,我吸收了作者的**模式识别**(他把"看财报"拆成 13 层,这个拆法本身在训练我);
- 我 → skill:我用自己的案例(cases/)把它调到贴合我。

"适配"是**两边一起逼近**的。我不是把 skill 拉低到我的水平,是在和它对齐的过程中被它拉高。

## 落点

- **cases/ 就是"适配"的施工记录。**
- 这不是新路——我做 pevc 财报透镜、港股 IPO 框架、chew 时都在走。今天做的是把它从"下意识"变成"自觉方法"。
