# 019 · Skill 必须同时规定“怎么想”和“怎么输出”

2026-07-30

## 这段对话

> 是因为我对于你输出的东西没有在 Skill 里规定，只是对于你思考的逻辑在 Skill 里规定了，所以你的输出逻辑很多都跳步了？

回答是：**是的，这就是核心原因，但需要说得更精确。**

原来的 `pevc-financials-lens` 主要规定了 AI 应该看什么、怎么算、怎样找替代解释、怎样控制证据边界，也就是规定了“分析引擎”。但它没有同等明确地规定：这些分析必须以什么结构出现在最终报告里，哪些中间逻辑不能被压缩，哪些关系必须画图，读者最终应该看见什么。

因此，AI 可能在运行过程中执行了不少分析动作，最终交付物却只留下：

```text
数据或事实
→ 一句结论
→ 尽调问题
```

内部做过推理，不等于已经把推理交付给读者。**思考协议不会自动变成输出协议。**

## 一个判断型 Skill 实际上需要两套契约

### 1. 思考与执行契约

它规定 AI 在后台怎样工作：

- 看哪些数据和文字；
- 使用什么定义和公式；
- 什么信号触发什么测试；
- 怎样提出竞争性解释；
- 怎样寻找支持、反证和缺失证据；
- 结论最多可以说到什么程度；
- 结果如何回填主框架和决策。

这套契约解决的是：**分析有没有做。**

### 2. 输出与交付契约

它规定读者最终必须看见什么：

- 章节按什么问题组织；
- 哪些数字必须解释口径、公式和大白话含义；
- 哪些判断必须展开机制、替代解释和证据权衡；
- 哪些趋势、构成和联动必须画图；
- 图表后必须写清支持什么、不能证明什么；
- S/J、来源、可推翻条件和投资影响放在哪里；
- 最终文件怎样检查格式、图片和阅读体验。

这套契约解决的是：**分析有没有被有效交付。**

两者缺一不可：

```text
只有思考契约
→ AI 可能想得很多，但报告把中间逻辑压掉

只有输出契约
→ 报告形式完整，却可能没有真正取证和判断

思考契约 + 输出契约 + 最终验收
→ 才形成可复核、可使用的 Skill
```

## 为什么没有输出规定时会自然跳步

模型生成最终文本时，会主动压缩它认为可以省略的中间过程。尤其在长报告里，它更容易：

- 用 S/J 标签代替证据权衡；
- 用一句“综合判断”代替商业机制；
- 把竞争性解释留在内部推理中；
- 用底表的完整性代替正文分析；
- 认为读者可以自行从三期数字看出趋势；
- 认为列出费用分项就等于说明了费用构成；
- 为控制篇幅而优先删除图表和解释桥。

这并不一定表示分析逻辑完全没有执行，而是 Skill 没有把“哪些内容必须显式出现在交付物中”设成完成门槛。

所以判断型 Skill 要采用一条严格规则：

> **没有进入最终交付物的关键推理，视为没有交付；无法被读者复核的内部思考，不能计入完成度。**

## 来福谐波暴露了什么

来福谐波案例中，Skill 已经规定了 13 层透镜、跨表测试、竞争性解释、证据等级和结论边界，因此数据提取和测试做了很多。但第一版最终报告仍然出现：

- 从客户留存、NRR 和渠道数据直接跳到持续性结论；
- 从费用率下降直接压缩成“不是销售硬推”；
- 底表有三期趋势，正文却没有把商业机制完整展开；
- 销售费用有明细和三期数据，却没有费用构成图与收入—费用率联动图。

问题不是再增加一条分析测试就能解决，而是要补上输出协议。后来增加的规则包括：

1. **关键数字五步解释**：数字是什么 → 怎么算 → 大白话是什么意思 → 不代表什么 → 下一步如何验证；
2. **决定性判断显式论证**：问题 → 事实与定义 → 商业机制 → 竞争性解释 → 证据权衡 → 当前裁决 → 可推翻条件 → 投资传导；
3. **费用效率双图**：费用构成图 + 收入—费用率联动图；
4. **图表解释边界**：每张图写清支持什么、不能证明什么；
5. **最终文档验收**：真正打开文件，以读者身份检查逻辑、图表和格式。

这些不是新的投资判断，而是把已有判断能力转化成读者可见的交付物。

## 把思考要求逐项映射为输出要求

以后设计 Skill，不能只写“要分析什么”，还要为关键思考动作指定可检查的输出痕迹：

| 思考动作 | 最终交付物中的痕迹 |
|---|---|
| 指标定义与重算 | 数字解释卡、公式、单位和来源 |
| 商业机制 | 从业务动作到收入、毛利、现金和风险的文字链 |
| 竞争性解释 | 至少一个替代原因及双方证据 |
| 证据权衡 | 为什么当前保留某种解释，S/J 到什么程度 |
| 趋势判断 | 三期以上折线、柱形或迷你趋势图 |
| 构成判断 | 分项金额、占比和可调节总额的构成图 |
| 跨表联动 | 收入—费用率、毛利—应收、利润—现金等联动图或桥图 |
| 结论边界 | 不能证明什么、缺少什么、什么会推翻 |
| 投资判断 | 对继续研究、估值、条款、融资或里程碑的影响 |

这张映射表的作用，是防止 Skill 把“思考过”误当成“交付过”。

## Skill 的完成定义应当改写

以后不能只问：

- 测试有没有执行？
- 公式有没有计算？
- 结论有没有形成？

还要继续问：

- 读者能否在正文中复原判断过程？
- 重要关系是否用合适的图表显现？
- 数字是否被目标读者理解，而不是只对专业人员可读？
- 图表、表格和标签有没有替代分析？
- 最终文件是否真的打开并通过验收？

因此，完整闭环应当是：

```text
规定怎么想
→ 规定怎么测试
→ 规定怎么输出
→ 运行真实案例
→ 验收最终交付物
→ 把暴露的问题同时回写思考协议与输出协议
```

这篇笔记与 [016 · 把抽象判断变成测试](016-把抽象判断变成测试.md)和 [018 · Skill 测试必须通过最终交付物验收](018-Skill测试必须通过最终交付物验收.md)构成连续关系：016 解决“判断怎样变成测试”，018 解决“为什么最终文档也要验收”，本文进一步解释这次失败的根因——**Skill 只规定了思考逻辑，却没有建立同等强度的输出逻辑。**

## 这次得到的一句话

> **一个可靠的判断型 Skill 必须同时拥有分析协议和输出协议：前者规定 AI 怎样得出判断，后者规定读者怎样看见、理解和复核这个判断。只有想对而没有交付清楚，仍然不算完成。**
