# 018 · Skill 测试必须通过最终交付物验收

2026-07-30

这次用 `pevc-financials-lens` 分析来福谐波，是一次很完整的真实回归：招股书数据提取、跨表计算、13 层扫描、专项测试、证据分级和结论回填都做了很多。但真正打开最终报告阅读后，才发现两个此前不容易从执行过程里暴露的问题：

- 分析逻辑展开不足，许多地方从数据直接跳到结论；
- 图表太少，趋势、构成和联动关系仍主要靠读者从文字和底表中自行拼接。

> 这次来福谐波就是很好的例子：数据提取和测试做了很多，但查看最终文档后，才发现“分析逻辑展开不足”和“图表太少”。说明一次 Skill 测试只有在最终交付物也通过验收后，才算真正完成。

## 执行完成，不等于测试完成

以前容易把 Skill 的完成标准放在执行侧：

- 数据有没有提取；
- 公式有没有重算；
- 测试有没有触发；
- 证据和结论有没有留下；
- 文件有没有成功生成。

这些都很重要，但只能证明 Skill **运行过**，不能证明它已经把判断有效交付给人。

来福谐波报告的底表、测试和结论比较完整，问题却仍然存在。原因不是“文字数量不够”，而是很多商业判断的中间逻辑没有在交付物中显式展开：读者能看见事实和最终裁决，却看不见事实怎样经过机制、竞争性解释和证据权衡变成裁决。

同样，表格里有三期数据，不等于读者已经看见趋势；文字里列出了费用分项，不等于读者能迅速看出费用花在哪里。图表不是装饰，而是把重要关系从底表里提出来，降低读者理解成本。

因此，一次真实回归至少要通过两层验收：

```text
执行验收
→ 数据、测试、计算、证据和结论是否完成

交付物验收
→ 逻辑是否看得见、数字是否看得懂、关系是否画得出、格式是否真的可用
```

第二层没有通过，Skill 测试仍未结束。

## 最终交付物的四道验收

### 1. 内容完整性验收

检查该取的数据、该执行的测试、该保留的证据边界是否都在。未执行项必须写清，不能把“没做”写成“没问题”。

### 2. 论证显式化验收

对最影响决策的 3—5 个判断，最终文档必须让读者看见：

```text
问题
→ 事实与指标定义
→ 商业机制
→ 竞争性解释
→ 支持、反对与缺失证据
→ 当前裁决及理由
→ 可推翻条件
→ 对决策的影响
```

S/J 标签、底表、风险清单和一句结论不能替代这条论证链。运行时“AI 心里想过了”，但最终文档没有写出来，等于没有交付。

### 3. 可视化与可读性验收

图表应当服务判断，而不是为了好看而增加。至少检查：

- 三期以上连续数据是否需要折线或柱形趋势图；
- 费用、收入或存货分项是否需要构成图；
- 收入与费用率、毛利与应收、利润与现金是否需要联动图或桥图；
- 关键数字是否解释了是什么、怎么算、大白话是什么意思、不代表什么、下一步怎样验证；
- 每张图是否写清“支持什么”和“不能证明什么”。

来福谐波销售费用就是一个具体例子。只写“2025 年销售费用 9.2，其中员工、样品、商务拓展和股权激励各是多少”仍然不够。最终报告应同时画：

1. **费用构成图**：回答钱花在哪里；
2. **收入—费用率联动图**：回答收入是否比销售投入增长更快。

但即使图上显示收入增长快于表内销售费用，也不能直接推出产品自然拉动增长。经销商可能承担获客，折扣和账期可能反映在毛利与应收，图表仍需接回竞争性解释和证据边界。

### 4. 文件成品验收

最后必须真的打开最终文件，而不是只确认生成命令成功。检查：

- 标题、目录、表格、图片和引用能否正常显示；
- 图表是否清晰，字号、单位、图例和颜色是否可读；
- 图片链接是否失效，表格是否溢出；
- 自用 md 是否便于继续批注和修改；
- 对外 Word/PPT 是否符合正式交付要求；
- 最终文档的重点、篇幅和格式是否符合使用者的阅读习惯。

格式问题并不只是美观问题。它会决定读者能否发现逻辑、复核数字和继续提出高质量反馈。

## Skill 回归测试的完整闭环

以后一次 Skill 测试按下面的闭环完成：

```text
选择真实案例
→ 执行 Skill
→ 检查数据与测试
→ 生成最终交付物
→ 以真实读者身份完整阅读
→ 验收论证、图表和格式
→ 发现缺口
→ 回写执行文件、原始反馈账本和修改决策
→ 重新生成并再次验收
```

这里最关键的一步是“以真实读者身份完整阅读”。执行者知道自己在后台做过哪些计算和判断，因此很容易自动补全交付物中缺失的逻辑；真实读者没有这些上下文。只有把自己切换到读者视角，才能发现哪些推理只存在于运行过程，哪些关系仍埋在底表里。

## 完成标准

一次判断型 Skill 的真实回归只有同时满足以下条件，才算完成：

- 数据、测试和证据边界完整；
- 关键判断的论证链在正文中可复核；
- 重要趋势、构成和联动关系得到恰当可视化；
- 图表没有替代分析，也没有越过证据得出结论；
- 关键数字能被目标读者理解；
- 最终文件已经打开并通过内容、呈现和使用体验检查；
- 验收发现的问题已经回写 Skill，而不只是临时修补当前报告。

## 这次得到的一句话

> **一次 Skill 测试不是以“程序跑完、文件生成”为终点，而是以最终交付物通过内容、论证、可视化和格式验收为终点。只有读者能够看懂、复核并使用，且暴露的问题已经回写 Skill，这次测试才真正完成。**
