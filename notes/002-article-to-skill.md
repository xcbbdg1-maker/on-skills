# 002 · 用别人的文章做成一个 skill:四步法

2026-07-27

接 [001](001-skill-acquisition-loop.md) 的"跑起来→研读→打磨适配"。当种子是**别人的一篇好文章**(而非现成 skill)时,把它变成自己 skill 的完整流程:

## ① 通读原文 + 就地注释 + 想清楚它会怎么进 skill

- 我(Claude)**先自己通读、真正弄懂作者的判断逻辑**,不是扫一遍就蒸馏。
- 原文存进 `sources/`,**看不懂的地方就地注释**(`> 📖[注]`,加粗被注句、多点分行、英文给全称)。
- 边读边想:每一句**抽象的表述,到 skill 里会被怎么落成可操作的透镜/checklist**。
- 若作者写得太简略,**我要补全**——把省略的逻辑写成完整的句子,别把"作者留白"直接带进 skill。

## ② 对照原文和做出来的 skill,审计遗漏

- 逐层/逐条对照 `sources/` 原文 与 `SKILL.md`:**skill 漏了哪些判断逻辑?它是怎么呈现这篇文章的框架的?**
- 判定"覆盖"的标准要严:不是"提到了"算,而是**能不能据此做出可证伪的判断**。
- 产出一份**对照审计**(见 [examples/pevc-lens-audit.md](../examples/pevc-lens-audit.md)),把"✅覆盖 / ⬜只在原文 / 该提升"写清楚,再决定补什么进 skill。

## ③ 拿真材料跑一遍,再打磨

- 以这个 skill 为例,**下载一份真招股书/年报**,运行 skill。
- **三方对照**:skill(方法)↔ 生成的分析 ↔ 招股书原文。看哪里透镜不好用、哪里该加提醒、哪里判断落不了地。
- 据此**进一步打磨 skill**(加"使用前先下报告"提醒、加尽调边界、改透镜措辞…都是这么逼出来的)。

## ④ 通读所有 skill 的 md,把名词啃透

- 通读**所有让 Claude 帮做的 skill 的相关 md**(SKILL.md / references / sources),**不懂的名词就地注释弄懂**。
- 目的:skill 不是"Claude 懂就行",是**要长到我脑子上**——我自己得先看得懂、认得每个词,它才算我的。

---

**一句话**:文章 → 通读补全 + 就地注释 → 对照审计遗漏 → 真材料实跑打磨 → 啃透每个词。前两步让 skill **忠实**,后两步让 skill **好用且属于我**。
