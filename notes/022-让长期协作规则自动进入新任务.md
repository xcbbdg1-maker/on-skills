# 022 · 让长期协作规则自动进入新任务

2026-07-31

## 这段对话

> 下次我想用你重新做任务的时候，我是不是让你先读取这个 MD 比较好？

答案是：手动提醒读取当然有效，但更好的方式不是每次重新提醒，而是把已经稳定的协作规则放进 Codex 会在新任务启动时自动读取的位置。

这次采用的做法是：

```text
GitHub 私有仓库保存主版本
→ 本地全局 AGENTS.md 保存当前生效版本
→ 新任务启动时 Codex 自动加载
→ 具体项目再用项目级 AGENTS.md 补充或覆盖
```

## GitHub 仓库本身不会自动变成新任务的规则

把长期协作偏好写进 GitHub 很重要，因为它提供了：

- 可追溯的主版本；
- 修改历史；
- 备份；
- 跨设备和跨环境恢复的入口；
- 规则为什么产生的说明。

但仅仅把文件放在 GitHub，并不意味着每个新任务都会自动读取它。新任务不会因为模型“记得上次”就自然恢复全部工作方式，私有仓库中的普通 Markdown 也不会自动进入当前指令链。

如果每次开场都要求“先去 GitHub 读取这个文件”，虽然可行，却仍然依赖用户记得提醒，也增加了一次联网、授权和读取步骤。

## 全局 `AGENTS.md` 才是自动加载层

根据 [Codex 官方说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md.md)，Codex 在每次新的运行开始时会建立一条指令链：

1. 先读取 Codex home 目录中的全局 `AGENTS.md`；
2. 再从项目根目录向当前工作目录读取项目级规则；
3. 越靠近当前工作目录的规则越具体，可以覆盖更上层的规则。

Windows 默认位置是：

```text
C:\Users\<用户名>\.codex\AGENTS.md
```

因此，把稳定的个人协作偏好放到全局 `AGENTS.md` 后，新任务不需要再次提醒。它适合保存：

- 默认使用什么语言和汇报方式；
- 什么情况下任务才算完成；
- 已确认的 GitHub 合并授权；
- 完整备份的验证要求；
- 反复出现的协作纠偏；
- 跨项目都适用的工作偏好。

## 三层结构比“每次重新解释”更可靠

### 第一层：GitHub 主档

`codex-working-playbook` 保存完整规则、来源、复盘和版本历史。它是长期维护的主版本，也是换电脑或重装环境时的恢复来源。

### 第二层：全局生效文件

`~/.codex/AGENTS.md` 保存需要在每个新任务中自动生效的规则。它应当保持相对简洁、稳定，并标明 GitHub 主档地址。

### 第三层：项目规则

某个仓库根目录的 `AGENTS.md` 只保存该项目特有的要求，例如：

- 必须运行哪些测试；
- 输出放在哪里；
- 哪些资料不能公开；
- Skill 的修改协议；
- 该项目特有的文件和术语。

这样，全局层负责“你希望 Codex 怎样与你协作”，项目层负责“这个项目具体怎样完成”。

## 为什么不应该把所有笔记都塞进全局规则

自动加载不等于加载越多越好。全局规则会占用每个任务的上下文，如果把所有复盘、案例和方法文章原样塞进去，可能导致：

- 新任务启动时携带大量无关内容；
- 真正重要的规则被埋没；
- 项目判断受到其他案例污染；
- 规则之间出现重复或冲突；
- 后续维护变得困难。

所以，应当区分：

```text
稳定、跨项目、必须自动执行的规则
→ 放进全局 AGENTS.md

详细解释、来源、案例和复盘
→ 留在 GitHub 工作手册

特定项目规则
→ 放进项目根目录 AGENTS.md

复杂且可复用的执行流程
→ 做成 Skill
```

## 同步不是一次复制，而是一项维护责任

GitHub 是主版本，本地文件是生效副本，两者之间可能出现漂移。以后更新长期协作规则时，应当同时完成：

1. 修改 `codex-working-playbook`；
2. 合并到 GitHub `main`；
3. 将最新规则同步到本地全局 `AGENTS.md`；
4. 核对关键规则已经出现；
5. 在新的 Codex 任务中验证指令已加载。

Codex 通常在一次运行开始时建立指令链。因此，在当前任务中途修改全局文件，不应假设当前任务会重新加载；新建任务或重新启动后才是验证自动生效的合适时点。

## 边界

全局规则不能覆盖安全、权限和隐私边界，也不能替代当前任务的明确指令。以下内容不应直接放入全局文件：

- 密钥和访问令牌；
- 客户隐私或保密材料；
- 只适用于一个仓库的大量技术细节；
- 尚未确认、可能频繁变化的个人偏好；
- 会绕过高风险操作确认的宽泛授权。

当前任务的明确指令优先，项目级规则负责更具体的约束，安全和权限边界始终保留。

## 这次实际执行的结果

本地原有的全局 `AGENTS.md` 是一个 0 字节空文件。它虽然存在，但不会产生实际规则。这次已经把 `codex-working-playbook` 中确认过的协作规则写入该文件，并加入 GitHub 主档地址。

这意味着从下一次新任务开始，Codex 可以自动取得这些长期协作偏好，不再要求用户每次重新发送“先读取这个 MD”。

## 这次得到的一句话

> **GitHub 负责保存长期协作规则的主版本，全局 `AGENTS.md` 负责让规则在新任务中自动生效，项目级 `AGENTS.md` 负责就近覆盖具体要求。真正好的协作记忆，不是让用户每次提醒 AI 去读，而是把稳定规则放进正确的加载层，并维护主档与生效副本的一致。**
