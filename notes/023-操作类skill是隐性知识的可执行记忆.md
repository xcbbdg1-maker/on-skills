# 023 · 操作类 Skill 是隐性知识的可执行记忆

2026-08-02

## 这次的想法

> 我觉得造操作类 Skill 的一个好处是：随着时间流逝，你会忘记自己当时会的这个技能里的隐性知识，但把它做成 Skill 就特别合适。

很多操作第一次做通时，并不是只学会了一条命令。

真正让它成功的，往往还包括一整组当时没有被明确写下来的判断：先检查什么、参数为什么这样填、出现某种报错意味着什么、哪一步不能重试、怎样才算真的完成。刚做完时，这些东西都在脑子里，所以会误以为自己已经“会了”。几个月后再做，最先消失的恰恰是这些上下文。

因此，操作类 Skill 的价值不只是自动化。它还在做一件更重要的事：

> **把当时仍然鲜活的操作记忆，固化成未来还能执行的外部记忆。**

## 最容易忘的不是步骤，而是步骤之间的判断

普通 SOP 可以记录：

```text
打开页面
→ 填入参数
→ 执行命令
→ 导出结果
```

但真正决定成败的隐性知识通常藏在步骤之间：

- 执行前如何判断环境是否正确；
- 哪些参数可以用默认值，哪些必须根据场景修改；
- 正常输出应该长什么样；
- 哪些警告可以继续，哪些报错必须停止；
- 失败后应从哪里恢复，怎样避免重复写入或破坏已有状态；
- 做完以后如何验证结果，而不是只看命令返回成功。

这些内容当时会觉得“不言自明”，过一段时间却最难从零还原。只保存命令，相当于保存了动作，却丢掉了当时会做这个动作的人。

## 从说明文档变成可执行资产

文档解决的是“以后还找得到”，操作类 Skill 进一步解决的是“以后还能做得出来”。

两者的区别可以这样理解：

```text
文档：告诉未来的我，当时是怎么做的
Skill：带着未来的我，按当时的判断把事情做完
```

Skill 可以把容易遗忘、容易输错、容易遗漏的部分封装起来，让人只需要重新提供当前任务的变量。它不仅保存知识，还把知识接回了行动。

这会形成一种很具体的复利：第一次解决问题时付出的搜索、试错和排障成本，不再只服务于当次任务，而是变成以后可以反复调用的能力。

## 最值得封装的三类操作

### 1. 学习曲线陡、细节密集的配置

例如特殊架构下的打包、复杂构建流程、依赖特定环境变量的工具链。这类操作未必经常发生，但每次重新查资料和恢复上下文都很贵。

### 2. 低频但高风险的操作

例如数据库备份与恢复、证书续签、生产环境排障。半年做一次，足以忘掉细节；一旦做错，后果又很重。此时 Skill 不应只负责执行，还要强制做目标确认、备份、范围校验和结果验收。

### 3. 多系统之间的长链路

例如：

```text
整理素材
→ 压缩与重命名
→ 上传对象存储
→ 生成固定格式链接
→ 回填到知识库
```

链路越长，越容易忘记顺序、字段映射和中间产物。Skill 的作用是把这些接口关系固定下来，减少每次重新拼接的成本。

## 一个操作真正值得进入 Skill 的信号

满足下面任意几条，就应该考虑在刚做通时立即沉淀：

- 为了做通它，查了多个来源；
- 遇到了文档没有写清的坑；
- 使用了难以凭记忆还原的参数、路径或配置；
- 中间需要根据结果做分支判断；
- 操作不常发生，但将来大概率还会发生；
- 出错成本明显高于封装成本；
- 下一次执行者可能不是现在的自己。

最好的沉淀时点不是“以后有空整理”，而是第一次做通之后。因为此时失败路径、关键判断和验证方法还没有从记忆里蒸发。

## 操作类 Skill 最少要保存什么

如果只把成功时敲过的命令复制进去，它仍然只是一个脚本片段。一个能替未来自己接手的 Skill，至少应保存：

1. **触发条件**：什么任务适合调用，什么情况不适合；
2. **输入与前置检查**：需要哪些参数、权限、工具和环境状态；
3. **执行步骤**：操作顺序，以及每一步为什么存在；
4. **分支与失败处理**：常见异常、停止条件、恢复方式；
5. **安全边界**：哪些动作需要确认，怎样限定影响范围；
6. **完成标准**：如何验证真实结果，而不是只验证流程跑完；
7. **变化入口**：外部系统升级后，应该优先检查和修改哪里。

这里最重要的是完成标准。没有验收的自动化，只是把“我执行了”变快；有验收的 Skill，才是在复现“我会做”。

## 需要保留的一点警惕

Skill 不会自动对抗时间。命令会变，API 会升级，页面会改版，权限和环境也会漂移。如果只封装一次、从不回归，它也会成为过期文档。

因此，操作类 Skill 保存的不应只是某一版固定答案，还要保存：

- 依赖版本或适用环境；
- 能暴露变化的前置检查；
- 能发现失效的最终验收；
- 每次重跑后将新坑写回去的修改入口。

这样，时间带来的变化不会被隐藏，而会在执行时尽早暴露，并重新进入 Skill 的更新循环。

## 这次得到的一句话

> **知识会随时间蒸发。造一个操作类 Skill，就是趁隐性知识还在，把“过去那个最懂这项操作的自己”保存成可执行资产；保存的不能只有步骤，还要包括前置条件、分支判断、失败处理和完成标准。**
